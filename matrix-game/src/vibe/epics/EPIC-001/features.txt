Mini Game Project - Initial Setup Epic

This mini project is a simple game site intended to be played between friends. Keep the implementation lightweight and do not overbuild. The goal of this epic is only to remove the default React/Vite boilerplate, create the basic page structure, set up routing, and prepare the project for deployment through GitHub Pages.

Use React with Vite.
Use .jsx files only.
Use react-router-dom for routing.
Keep the structure simple and easy to extend later.
Do not add game logic yet.
Do not add unnecessary styling frameworks or extra dependencies unless specifically required.

Repository name:

matrix-game

Important layout rule:

- The normal player-facing pages should always behave like a mobile app.
- On desktop, the app should display at mobile width and be centered on the screen.
- Do not create a full desktop layout.
- Do not add responsive desktop-specific layouts.
- Keep the visual structure focused on mobile use.

Pages affected:

- Start
- Player
- Score

These pages should use the mobile-width app shell.

Suggested layout behavior:

- The main app container should have a maximum mobile-style width.
- On larger screens, this container should be centered horizontally.
- The app should still fill the available height nicely.
- Content should be easy to tap on a phone.
- Buttons should be large enough for mobile use.
- Spacing should be clean and simple.

The iPad exception:

The iPad page is different from the normal player-facing pages.

- The iPad page is intended to be used on an iPad.
- It can use a wider layout than the other pages.
- It should not be restricted to the same narrow mobile width as the Start, Player, and Score pages.
- The iPad page can have its own wider page shell or modifier class.

Navigation changes:

- Hide the normal visible navigation link to the iPad page.
- Most players should not see or use the iPad page link.
- The iPad page should only be accessible from a small icon in the top-right area of the app.
- The icon should be subtle, because it is for a special circumstance.
- The icon should route to /ipad when clicked.
- Keep the normal player navigation simple.

Requirements:

- Add a mobile app shell for normal pages.
- Add different layout handling for the iPad page.
- Center the mobile shell on desktop screens.
- Keep desktop behavior simple and only useful for development.
- Add basic styling for:
  - Page shell
  - Page content area
  - Mobile-width container
  - iPad-width container
  - Top-right iPad access icon
  - Large mobile-friendly buttons
- Do not add game logic in this feature.
- Do not add language or difficulty selection logic in this feature.
- Do not over-design the final UI yet.
- The goal is only to create the aesthetic structure that future features will use.

Expected demo:

- On a mobile-sized screen, Start, Player, and Score should look like mobile pages.
- On desktop, Start, Player, and Score should appear as a centered mobile-width app.
- The iPad page should be wider than the other pages.
- There should be no normal nav link to the iPad page.
- The iPad page should be reachable by clicking a small icon in the top-right area.
- The app should still route correctly between all existing pages.


Feature-004 - Start Page Language and Difficulty Selection
Status: done

Implement the start page options that prepare the player for the game.

The start page needs to collect two choices from the player:

1. Language
2. Difficulty

This site will be bilingual and used in both English and Japanese.

Language selection:

When the user arrives on the Start page, the first question should ask which language they want to play the game in.

The language options should be:

- English
- Japanese

Requirements:

- The language choice should be selected using buttons.
- Do not use dropdowns.
- Do not use radio buttons.
- Pressing a language button should immediately submit that choice.
- After the player chooses a language, move them to the next question.
- The selected language should be stored somewhere accessible by the rest of the app.
- The selected language should not change after it has been chosen during this game flow.
- Once the language has been selected, remove or hide the iPad access icon from the Start page.
- The iPad option should only be available before the normal player begins the game setup.

Difficulty selection:

After the player selects their language, ask what difficulty they want to play.

The difficulty options should be:

- Easy
- Medium
- Hard

Requirements:

- The difficulty choice should be selected using buttons.
- Do not use dropdowns.
- Do not use radio buttons.
- Pressing a difficulty button should immediately submit that choice.
- Once the difficulty has been selected, move the user to the Player page.
- The selected difficulty should be stored somewhere accessible by the rest of the app.

Flow requirements:

- Start page opens.
- User sees the language question first.
- User selects English or Japanese by pressing a button.
- The app saves the selected language.
- The app moves to the difficulty question.
- The iPad access icon is hidden after language selection.
- User selects Easy, Medium, or Hard by pressing a button.
- The app saves the selected difficulty.
- The user is routed to /player.

State requirements:

- Add a simple app-level state structure for storing:
  - selectedLanguage
  - selectedDifficulty
- Keep this state simple for now.
- It only needs to work during the current session.
- It does not need to survive a page refresh yet.
- Do not build a full backend or persistence layer.
- Do not add player name logic yet.
- Do not add scoring logic yet.

Bilingual text requirements:

When English is selected, future visible game text should be able to use English labels.

When Japanese is selected, future visible game text should be able to use Japanese labels.

For this feature, include bilingual labels for the Start page flow.

Suggested English text:

Language question:

Language buttons:
English
Japanese

Difficulty question:

Difficulty buttons:
Easy
Medium
Hard

Suggested Japanese text:

Difficulty buttons:

Implementation guidance:

- Consider creating a simple game context or app state provider.
- The context can store selectedLanguage and selectedDifficulty.
- The Start page can update this context when buttons are clicked.
- The Player page can later read from this same context.
- Keep the implementation lightweight.
- Do not overbuild a full translation system yet.
- A simple labels object is enough for now.
- Use react-router-dom navigation after the difficulty is selected.

Expected demo:

- Visiting / should show the language selection first.
